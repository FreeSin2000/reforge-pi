# 排版与美观清单

> 目标：图在**等宽字体 + git diff + GitHub markdown** 三种环境下都对齐、可读、可改。

## 字符集选择（一篇内统一）

两种风格二选一，**别混用**：

- **纯 ASCII**（最稳，任何字体/终端都对）：`+ - | / \ < > ^ v = >`
- **Box-drawing**（更美观，现代终端/markdown 支持好）：
  `┌ ┐ └ ┘ ─ │ ├ ┤ ┬ ┴ ┼` 和 `▲ ▼ ► ◄`

不确定时选纯 ASCII。要提交到 git、被别人用各种字体看，纯 ASCII 最保险。

## 宽度

- **硬上限 100 列**，目标 **≤ 80 列**（GitHub 代码块、终端、邮件都能容纳）。
- 超宽优先**拆成两张图**，而不是缩小字号或删信息。
- 检查：`awk '{ if (length($0)>m) m=length($0) } END{print m}' <图文件>`。

## 中文对齐（最容易翻车）

等宽字体里中文字符通常占 **2 列**，但很多渲染器/字体不一致，导致竖线错位。

规则：
1. **图框内只用英文、数字、符号**（函数名、结构体名、地址）。
2. 中文说明放在**图外**的段落里，或图右侧用足够空格分隔后再放（仍可能错位，慎用）。
3. 必须用中文时，**同一列的中文行要等长**，或干脆放弃竖线对齐、改用缩进式。

## 缩进与对齐

- 用**空格**缩进，不用 Tab（Tab 宽度可变）。
- 关键列（箭头 `│`、分支 `├─`）**全局对齐到同一列**。
- 树状子项：`├─` 用于中间项，`└─` 用于最后一项。
- 右对齐标注（如地址、字段名）比左对齐更整齐。

## 标注约定

- 节点带证据：`file:line  symbol` 或 `path:line`。
- 箭头旁写**含义**：控制流写条件，数据流写参数/寄存器。
- 顶部给**标题带**（`════ name ════`），底部给**一句话结论**。
- 图例只在符号不直观时给，别每张都加。

## 保持可维护

- 图是**文本**：改了源码就改图，别让图比代码旧。
- 一张图只讲**一件事**；太大的链拆成「总览图 + 分图」。
- 把定义性的长图放 `diagrams/<topic>.md`，正文只放缩略总览。

## 美观 checklist

- [ ] 宽度 ≤ 80（最多 100）
- [ ] 竖线/箭头全部对齐
- [ ] 同一张图字符集统一
- [ ] 框内无中文（或已确认对齐）
- [ ] 每个关键节点有 `file:line`
- [ ] 箭头语义一致（▼/►/═►）
- [ ] 顶部标题带、底部一句结论
- [ ] 无 Tab、无尾随空格

## 反模式

- ❌ 混用 `-` 和 `─` 画同一条线。
- ❌ 图里塞整段中文句子。
- ❌ 节点没有证据，读者无法核对。
- ❌ 一张图试图表现所有细节（应拆图）。
- ❌ 箭头方向来回跳（先下再上再下）。
