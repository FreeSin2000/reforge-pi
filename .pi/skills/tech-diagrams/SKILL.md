# 技术图解（ASCII）

把源码分析结论画成**纯 ASCII 图**，内嵌进 `notes/`，让读者一眼看懂结构和流向。

## 何时画

出现下列任一场景，就先画图再解释：

- **控制流 / 调用链 / 启动流程**（例：bootloader → `start_kernel`）。
- **时序 / 状态迁移 / 生命周期**（例：进程状态机、锁的获取释放）。
- **内存 / 地址空间布局**（例：解压前后布局、页表层级）。
- **数据流 / 所有权传递**（例：`boot_params` 被层层传参）。
- **分层 / 组件关系**（例：VFS → FS → block → driver）。

一句话：读者会在脑子里画图的地方，就直接替他画出来。

## 选哪种图

| 你要表达 | 图型 | 模板 |
|---|---|---|
| 阶段推进的调用链 | 阶段流水线 pipeline | `references/patterns.md` §1 |
| 多方的先后交互 | 时序 sequence | §2 |
| 状态迁移 | 状态机 state | §3 |
| 内存 / 地址空间 | 布局图 layout | §4 |
| 结构体 / 链表 / 树 | 数据结构 | §5 |
| 分层 / 组件 | 分层架构 | §6 |
| 一个数据的旅程 | 数据流 dataflow | §7 |
| 分支 / 决策 | 决策树 | §8 |

## 硬规则

1. **只用 ASCII / box-drawing 字符**，一篇内风格统一（见 `style.md` 的字符集选择）。
2. **宽度 ≤ 100 列**；能进 80 列更好。超宽就拆图，不要缩字。
3. **每个关键节点标注证据**：`文件:行 符号`（如 `arch/x86/boot/header.S:538 start_of_setup`）。图本身是证据，节点必须真实，不臆造。
4. **方向统一**：主流程自上而下；数据流可自左而右。
   箭头语义固定 —— `▼` 控制流、`►` 数据/参数流、`═►` 跨层/跳转/入口。
5. **中文慎入图内**：等宽字体下中文占 2 列、极易错位。函数名/标识符保持英文；中文说明尽量放图外。
6. **阶段分隔**用 `════` 标题带；**子步骤**用 `├─ / └─`。
7. **图后附一句话**点明这张图要说的结论（不要只丢图）。

## 输出位置

- 默认**内嵌**进对应 `notes/<project>/*.md`。
- 多图 / 大图放 `notes/<project>/diagrams/<topic>.md`，正文引用。
- 图与 journal 条目互相引用：journal 写结论，图放在要 promote 的目标文档里。

## 自检（写完必跑）

图写完先用脚本过一遍，再交给读者：

```bash
python3 scripts/lint.py notes/<project>/diagrams/*.txt
```

检查：显示宽度（中文按 2 列）、尾随空格、Tab、**框内中文**、非白名单字符、字符集混用。
退出码非 0 即需修。注意它只查“确定性”问题，图型/信息量仍需人工判断。
